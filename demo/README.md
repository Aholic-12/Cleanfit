# Cleanfit · Pose Mirror

浏览器端的姿态镜像原型：摄像头取景 + 实时 3D 人像复刻 + 体表测量标注。

![预览](../assets/badge-status.svg)

## 跑起来

```bash
python demo/serve.py          # 默认 http://127.0.0.1:8848
python demo/serve.py 9000     # 指定端口
```

必须用 `serve.py`（或任意静态服务器）打开，**不能双击 `index.html`**：
浏览器的摄像头 API 只在安全上下文（`https` 或 `http://localhost`）下可用，
`file://` 既拿不到摄像头，也会被 CORS 拦住 wasm 加载。

没有摄像头也能看效果：

```
http://127.0.0.1:8848/?demo=1
```

演示模式用一段合成姿态驱动人像（呼吸起伏 + 手臂摆动 + 头部轻微转动），
用来验证渲染管线，也方便截图。

## 4D 精准测量工作台（`measure.html`）

主页面右上角的「**精准测量 →**」进入独立工作台（也可直接打开 `measure.html`）。
主页的指标面板是给试衣用的**单帧粗测**；要拿可信的尺寸数值用这个页面。

**为什么需要单独做一套。** BlazePose 的 `poseWorldLandmarks` 虽然以米为单位，
但那是**模型先验尺度**——网络会把高个子往平均值压、矮个子往平均值抬，
再用它反推肩宽、胯宽会带上系统性偏差。单帧还有关键点抖动、遮挡误检、
侧身时的透视缩短。所以这里不追求「实时好看」，只追求**测得准**：

> **4D = 3D 骨架段长（与视角无关，转体不改变长度） × 时间序列多样本稳健融合。**

| 环节 | 做法 |
|:---|:---|
| **限定区域 ROI** | 画面上拖拽框选。过滤下沉到「段」级：框全身才出身高/腿长，只框上半身就只出肩宽/臂长，腿部关键点出框的帧不污染上半身数据 |
| **姿态分桶** | 按肩向量朝向与髋部位移自动分成 正面 / 抬臂 / 斜侧 45° / 侧身 90° / 移动 五类，页面逐步引导，避免 500 帧全是同一个姿势（重复帧不增加信息） |
| **质量评分** | 关键点可见度、ROI 命中率、正面程度、极端运动模糊，低质量帧直接丢弃 |
| **稳健融合** | 每项指标 MAD 离群剔除 → 10% 截尾 → 质量加权均值；输出 CV（变异系数）、样本数、姿态覆盖、置信度、是否收敛 |
| **尺度标定** | 把模型先验尺度映射成真实厘米，见下表 |
| **卷尺锚点** | 结果表每行可填实测值，直接覆盖该项，作为校准锚点 |
| **多设备** | 切换不同摄像头继续采样会并入同一份样本（多视角）；激光测距作为外部尺度输入；预留深度源接口 |
| **导出** | JSON / CSV，含每项数值、CV、样本数、标定方式、ROI、视角数 |

### 采集效率与鼠标交互

| 控件 | 作用 |
|:---|:---|
| **直接在画面上拖框** | 空白处按住鼠标拖出新 ROI，**不用先点按钮**；框内拖动＝移动，拖边框/四角＝缩放，双击＝删除；8 个手柄让可编辑状态一眼可见，拖动时采样实时按新区域过滤 |
| **画面比例** | 默认 **4:3 全身优先**（640×480）。16:9 通常是 4:3 传感器上下裁切出来的，切 4:3 能多拿到一截垂直视野，最容易解决「人拍不全」；也可切 16:9 高清 / 1080p，切换会自动重新协商摄像头分辨率 |
| **入画检测** | 头顶 / 脚部 / 左右任一出画就在画面下方给出黄条提示，并给出「后退 30–60cm」「切 4:3」「分两段采集」三条具体建议 |
| **半身拼接** | 摄像头实在装不下全身时：先框上半身采一轮，再框下半身采一轮，**样本不清空**，各指标各自累积，最终合并出全身数据 |
| **采样灵敏度** | 1–10 档（默认 8），同时放宽「整帧质量门槛」和「单点可见度门槛」；高档几乎每帧都收，低档只留最稳的帧。顶栏实时显示 `fps` 与本帧质量 `Q` |
| **采集模式** | 快速（40 帧 + 1 类姿态，站着不动也能几秒出结果）/ 标准（90 帧 + 2 类）/ 高精度（200 帧 + 4 类）。收敛阈值由引擎 `result(calib, opts)` 配置，UI 进度条按当前模式的目标数走 |
| **达标自动停止** | 满足样本数 + 姿态覆盖 + CV 阈值就自动收尾并提示「采集完成」，不必一直等；想更准就取消勾选继续采 |

导出 JSON 里带 `capture`（模式 / 灵敏度 / 画面比例 / 收敛阈值）与 `roi`、`referenceBox`、`viewports`，便于复现实验。

**尺度标定四选一**（右上 CALIBRATION 面板）：

| 方式 | 需要 | 适用 |
|:---|:---|:---|
| 已知身高（推荐） | 填真实身高 cm | 最省事，把整副骨架按比例缩放到真值 |
| 参照物 A4 同平面 | 把 A4 举在身体同一深度，点「框参照物」框住短边 | 不需要测距仪，靠 `人体像素高 / A4 像素宽 × 21cm` |
| 激光测距 + 参照物 | 激光量人到相机距离 + 参照物框及其距离 | A4 与人体不同深度时，用针孔模型 `f = px·Z/W` 分别折算 |
| 仅激光测距 | 激光量距离 | 焦距由 65° 水平视角估算，标为「粗」 |

> **硬件现状（实测）**：本机 `Intel RealSense SR300` 的 Depth 设备在 Windows 中处于 `Error`，
> 且 `pyrealsense2 2.59` 已不再支持 SR300（`query_devices()` 返回 0 台），
> 浏览器 `getUserMedia` 也读不了 Z16/Y8 格式 —— **真实深度流当前拿不到**。
> 因此绝对尺度改由「激光测距 / 已知参照物 / 已知身高」这类外部基准提供。
> 若将来接上 D4xx / LiDAR，实现
> `window.CleanfitDepthSource = { getDistanceM(u, v, t) -> number }` 即可自动并入标定，
> 前端与测量引擎无需改动。

**演示模式**：`measure.html?demo` 用合成 3D 姿态驱动，无摄像头也能跑通
「采样 → 5 桶覆盖 → 收敛 → 导出」全链路，6 秒覆盖一轮姿态。

**算法验证**（合成骨架序列，4mm 关节高斯噪声 + 5% 离群帧 + 5 种姿态，400 帧）：
视角旋转 90° 后 3D 段长变化 `0.000000`；融合后身高误差 `0.000cm`、
肩宽误差 `0.009cm`，平均 CV `0.79%`、置信度 `0.956`、离群剔除 19 帧。
这说明**融合算法本身能压掉随机噪声和误检**；快速模式另测 70 帧恒定姿态即判定收敛。
真实场景的最终精度仍取决于标定质量、关键点稳定性与遮挡情况，
**围度类（胸/腰/臀围、臂展）是经验系数估算，不是实测**。

## 界面说明

- **左侧 CAMERA**：摄像头画面，叠加骨架、关节与三条测量线（肩 / 腰 / 胯，单位 cm）
- **传感器条**：当前设备名、类型标签（RGB / RGB·RS / DEPTH）、分辨率与帧率、
  深度流接入状态、自动增益倍率
- **中间 3D**：全息人像（钢铁侠 J.A.R.V.I.S 那种半透明青蓝、边缘辉光、扫描线），
  可拖拽旋转、滚轮缩放
- **右侧 AD FITTING**：独立试衣窗口，上传一张衣服图片就实时贴到真实人物身上
- **底部按钮**：启动/关闭摄像头（同一个按钮双态切换）、镜像、掩码扫描带、骨骼显隐、设备诊断
- **指标面板**：身高、肩宽、腰宽、胯宽、肩胯比 SHR、身形判定、有效关键点数

如果机器上有多个摄像头（比如内置 + USB），用左下角的下拉框切换，
`USB Camera` 这类 UVC 免驱设备浏览器可以直接访问，不需要装厂商 SDK。

## AD 试衣（单独窗口，实时贴到真实人物身上）

右侧 AD FITTING 是一个独立窗口，和中间的 3D 全息人像互不影响。点上传区或把
图片拖进去，衣服就会实时贴到摄像头里的真实人物身上。流程分三步：

1. **抠白底** —— 从图片四边做洪水填充，只吃和边缘连通的白色。
   不能按亮度全局一刀切，否则衣服印花里的白色（白底 logo、白色条纹）
   会一起被抠成透明，贴上去就是一个一个露肉的洞。
2. **裁边** —— 按 alpha 包围盒裁掉商品图四周的白边，衣服才能铺满躯干。
3. **贴图** —— 用 BlazePose 的 2D 关键点（肩 11/12、胯 23/24）构造一个躯干
   轮廓，把衣服图做 6×12 网格变形铺上去。衣服保留自己的 alpha 轮廓
   （T 恤形状），不是一块矩形。

「衣长」滑块控制下摆位置（1.0 刚好过胯线，0.7 露腰，1.35 盖住大腿根）。

### 怎么把「贴纸感」压下去

单纯把图贴到人身上，一眼就是一张贴纸。这里有五层处理，缺一层就露馅：

| 处理 | 解决的问题 |
|---|---|
| **离屏合成层 + `source-atop`** | 光影只落在已经画了布的像素上，不会漏到背景和皮肤上，也就不需要额外的遮罩 |
| **领口 `destination-out` 挖空** | 领口是真的把布挖掉一块、露出下面的脖子，不是一个盖上去的黑色椭圆。布口再压一圈细暗边做出厚度 |
| **圆柱体积 + 顶光 + 纵向褶皱** | 两侧压暗、正面提亮，肩亮下摆暗，再叠几条低频竖条当褶皱。衣服从「平面」变成「包着身体的曲面」 |
| **环境光匹配** | 每 12 帧把视频缩成 1×1 取平均亮度，画面暗就把衣服一起压暗，避免衣服像自带背光 |
| **袖缝几何** | 袖子不是另画一根管子，而是从肩点沿手臂轴线长到腋下，内边贴着衣身，才不会像挂在肩上的两块垫子 |
| **遮挡还原** | 用 BlazePose 的 z 判断手臂是否挡在身前，是的话把视频帧沿手臂区域贴回去，衣服不会盖在手臂上 |

另外两处细节：网格每个三角向外扩 0.9px，消除相邻格之间 clip 抗锯齿留下的接缝
（不扩的话整件衣服会浮出 6×12 的网格）；合成时先画一层轻微模糊打底再叠清晰层，
边缘是柔的而不是硬锯齿。

### 这条路线能走到哪

上限就在这儿：没有布料物理、没有真实的遮挡与阴影投射，凑近看还是「贴上去的」。
要完全达到扩散模型那种效果（每一帧重新生成穿着衣服的你），必须接云端实时
VTON —— 具体方案和成本见 [`docs/recon-tryanywear.md`](../docs/recon-tryanywear.md)。

### AI 精修（本地 GPU，可选）

纯 canvas 的短板是「布料是假的」。`tryon_server/` 里有一个本地 GPU 服务，
用 SD1.5-inpainting 对**已经贴好的躯干区域**做一次局部重绘：模型看得见人物、
姿势、光线和衣服的花纹，能把这块重新画成穿在身上的衣服。

关键是它只重绘**一次**：重绘结果会做一次逆变换（`FittingView.applyRefined`，
把每个网格单元从画布坐标采样回 UV 空间）烘焙成新的衣服贴图，之后的实时追踪
仍然由 canvas 负责 —— 所以画质是 AI 的，帧率还是 60fps。

```bash
# 一条命令全起来（精修服务 + 静态站点 + 浏览器）
start_demo.bat

# 或者手动
tryon_server/start.bat          # 精修服务，端口 8787
python -m http.server 8851 --directory demo
# → http://127.0.0.1:8851/
```

实测（RTX 5070 12G）：模型加载 4.6s，一次重绘 **1.3s**（768×576 / 22 步 / strength 0.45）。
模型文件放在 `.models/sd15-inpaint/`（约 2.2GB，fp16）。

面板上的「AI 精修」按钮：点一下，等 2-5 秒，衣服会被重绘并自动回贴。
「重绘」滑块控制强度 —— 调高模型改动更多（褶皱更自然，但花纹可能走样），
调低更忠于原图。

> 注意：线上分享链接是 https，调 `http://127.0.0.1` 会被混合内容策略拦截，
> 所以 AI 精修只在本地打开时可用；其余功能线上照常。

## 用 Intel RealSense 深度相机（SR300 / D4xx）

RealSense 在 Windows 上会注册成**两个独立的视频设备**：

| 设备管理器里显示 | 浏览器能用吗 | 说明 |
|:---|:---|:---|
| `… Camera SR300 Depth` | **不能** | 输出 Z16 / Y8 深度与红外格式，`getUserMedia` 不支持 |
| `… Camera SR300 RGB` | 能 | 标准 UVC 彩色流 |

所以「识别不到摄像头」很多时候不是故障：**深度流打不开是格式问题，装什么驱动都没用**。
页面会自动跳过深度设备、优先开 RGB 那一路，传感器条上会标出当前用的是哪种：

```
● RGB·RS  RealSense SR300 RGB   1280×720 · 30fps   DEPTH 待接入   GAIN 1.28×
```

`DEPTH 待接入` 表示检测到了深度设备，但深度流还没接进来。真要用深度数据做
精确测量，得走 Python + `librealsense`，把点云通过 WebSocket 推给前端渲染：

```bash
pip install pyrealsense2 numpy
```

前端渲染层不用改，只要把 `onResults` 的数据源从 BlazePose 换成后端推送即可。

> **实测补充（2026-11）**：本机 SR300 装上 `pyrealsense2 2.59.1` 后
> `rs.context().query_devices()` 返回 **0 台** —— 新版 librealsense 已移除 SR300 支持，
> 且 Depth 设备在设备管理器里是 `Error`。所以老 SR300 走 Python 同样拿不到深度帧；
> D4xx 等仍受支持的型号可以照上面接。替代方案见上文「4D 精准测量工作台」。

### 传感器条上的 GAIN

SR300 的 RGB 在室内弱光下噪点很大，BlazePose 直接吃原帧容易丢点。
页面每 10 帧估一次平均亮度，低于阈值就把整帧提亮后再送推理（最高 2.2×）。
点 `GAIN` 那个标签可以关掉自动增益。如果画面本来就很亮却还是检测不到人，
先看是不是曝光过度——提亮只会让过曝更糟。

## 技术选择

**为什么用 BlazePose 而不是 MoveNet。** MoveNet 只给 17 个 2D 关键点，
要拿到 3D 得自己再套一个 lift 网络。BlazePose 直接输出 `poseWorldLandmarks`——
33 个点，**以米为单位、以髋部中心为原点的世界坐标**，这才是「3D 复刻」能成立的前提。

**为什么全部依赖本地化。** `demo/vendor/` 里放着 three.js 与 MediaPipe 的
wasm / tflite / 二进制资源，页面零外链。原因是国内网络访问 jsDelivr 和
`storage.googleapis.com` 都不稳定，一旦某个 wasm 拉不下来整个页面就白屏。
本地化之后可以离线跑，也能直接部署到 GitHub Pages。

**测量为什么要用分割掩码。** 服装语境下的「肩宽」是三角肌外缘距离、
「胯宽」是大转子外缘距离，都不是关节中心距。用关键点直接算会得到
肩胯比 2.0 这种离谱数字（髋关节中心距只有 17cm 左右）。
所以这里逐行扫描人像分割掩码取外轮廓宽度，再用身高做像素→米的定标。

## 已知限制

- **主页指标面板的精度**：单目 RGB 单帧值，尺度是模型先验估计，身高误差约 ±5%，
  宽度误差更大，只适合给试衣提供大致体型。**要拿可信数值请用
  [`measure.html`](#4d-精准测量工作台measurehtml)**：多帧/多姿态/多视角融合 +
  外部尺度标定 + 稳健统计，并可填卷尺实测锚点。
  没有深度/激光等外部尺度基准时，任何单目方案都只能保证「比例」而非绝对厘米。
- **遮挡**：手挡住身体、侧身超过 60°、下半身出画时，关键点置信度会掉，
  低于 0.28 的点会被隐藏，人像会出现断裂。
- **性能**：lite 模型 + 分割在桌面 CPU 上约 20-30 fps；开启掩码扫描会再降几帧，
  已做每 3 帧算一次的节流。
- **光照**：画面过暗时检测会直接失败。页面自带自动亮度增益（最高 2.2×），
  但增益只会放大已有的信号——真的没有光，画面全黑时任何提亮都救不回来。
  先把环境照亮，或在系统相机设置里关掉自动曝光手动调高。
- **试衣仍是近似**：衣服按肩/胯关键点做网格变形贴在真实人物画面上，
  有体积明暗、褶皱和手臂遮挡，但没有真正的布料物理，也没有阴影投射。
