# Cleanfit · Pose Mirror

浏览器端的姿态镜像原型：摄像头取景 + 实时 3D 人像复刻 + 体表测量标注。

![预览](../assets/badge-status.svg)

## 跑起来

```bash
python demo/serve.py          # 默认 http://127.0.0.1:8848
python demo/serve.py 9000     # 指定端口
```

必须用 `serve.py`（或任意静态服务器）打开，**不能双击 `index.html`**：
浏览器的摄像头 API 只在安全上下文（`https` 或 `http://localhost`）下可用，
`file://` 既拿不到摄像头，也会被 CORS 拦住 wasm 加载。

没有摄像头也能看效果：

```
http://127.0.0.1:8848/?demo=1
```

演示模式用一段合成姿态驱动人像（呼吸起伏 + 手臂摆动 + 头部轻微转动），
用来验证渲染管线，也方便截图。

## 界面说明

- **左侧 CAMERA**：摄像头画面，叠加骨架、关节与三条测量线（肩 / 腰 / 胯，单位 cm）
- **传感器条**：当前设备名、类型标签（RGB / RGB·RS / DEPTH）、分辨率与帧率、
  深度流接入状态、自动增益倍率
- **中间 3D**：全息人像（钢铁侠 J.A.R.V.I.S 那种半透明青蓝、边缘辉光、扫描线），
  可拖拽旋转、滚轮缩放
- **右侧 AD FITTING**：独立试衣窗口，上传一张衣服图片就实时贴到真实人物身上
- **底部按钮**：启动/关闭摄像头（同一个按钮双态切换）、镜像、掩码扫描带、骨骼显隐、设备诊断
- **指标面板**：身高、肩宽、腰宽、胯宽、肩胯比 SHR、身形判定、有效关键点数

如果机器上有多个摄像头（比如内置 + USB），用左下角的下拉框切换，
`USB Camera` 这类 UVC 免驱设备浏览器可以直接访问，不需要装厂商 SDK。

## AD 试衣（单独窗口，实时贴到真实人物身上）

右侧 AD FITTING 是一个独立窗口，和中间的 3D 全息人像互不影响。点上传区或把
图片拖进去，衣服就会实时贴到摄像头里的真实人物身上。流程分三步：

1. **抠白底** —— 从图片四边做洪水填充，只吃和边缘连通的白色。
   不能按亮度全局一刀切，否则衣服印花里的白色（白底 logo、白色条纹）
   会一起被抠成透明，贴上去就是一个一个露肉的洞。
2. **裁边** —— 按 alpha 包围盒裁掉商品图四周的白边，衣服才能铺满躯干。
3. **贴图** —— 用 BlazePose 的 2D 关键点（肩 11/12、胯 23/24）构造一个躯干
   四边形，把衣服图做双线性网格变形铺上去。衣服保留自己的 alpha 轮廓
   （T 恤形状），不是一块矩形。

「衣长」滑块控制下摆位置（1.0 刚好过胯线，0.7 露腰，1.35 盖住大腿根）。
当前是「简单贴图」版本，后续再做布料褶皱、光照匹配、遮挡和物理模拟。

## 用 Intel RealSense 深度相机（SR300 / D4xx）

RealSense 在 Windows 上会注册成**两个独立的视频设备**：

| 设备管理器里显示 | 浏览器能用吗 | 说明 |
|:---|:---|:---|
| `… Camera SR300 Depth` | **不能** | 输出 Z16 / Y8 深度与红外格式，`getUserMedia` 不支持 |
| `… Camera SR300 RGB` | 能 | 标准 UVC 彩色流 |

所以「识别不到摄像头」很多时候不是故障：**深度流打不开是格式问题，装什么驱动都没用**。
页面会自动跳过深度设备、优先开 RGB 那一路，传感器条上会标出当前用的是哪种：

```
● RGB·RS  RealSense SR300 RGB   1280×720 · 30fps   DEPTH 待接入   GAIN 1.28×
```

`DEPTH 待接入` 表示检测到了深度设备，但深度流还没接进来。真要用深度数据做
精确测量，得走 Python + `librealsense`，把点云通过 WebSocket 推给前端渲染：

```bash
pip install pyrealsense2 numpy
```

前端渲染层不用改，只要把 `onResults` 的数据源从 BlazePose 换成后端推送即可。

### 传感器条上的 GAIN

SR300 的 RGB 在室内弱光下噪点很大，BlazePose 直接吃原帧容易丢点。
页面每 10 帧估一次平均亮度，低于阈值就把整帧提亮后再送推理（最高 2.2×）。
点 `GAIN` 那个标签可以关掉自动增益。如果画面本来就很亮却还是检测不到人，
先看是不是曝光过度——提亮只会让过曝更糟。

## 技术选择

**为什么用 BlazePose 而不是 MoveNet。** MoveNet 只给 17 个 2D 关键点，
要拿到 3D 得自己再套一个 lift 网络。BlazePose 直接输出 `poseWorldLandmarks`——
33 个点，**以米为单位、以髋部中心为原点的世界坐标**，这才是「3D 复刻」能成立的前提。

**为什么全部依赖本地化。** `demo/vendor/` 里放着 three.js 与 MediaPipe 的
wasm / tflite / 二进制资源，页面零外链。原因是国内网络访问 jsDelivr 和
`storage.googleapis.com` 都不稳定，一旦某个 wasm 拉不下来整个页面就白屏。
本地化之后可以离线跑，也能直接部署到 GitHub Pages。

**测量为什么要用分割掩码。** 服装语境下的「肩宽」是三角肌外缘距离、
「胯宽」是大转子外缘距离，都不是关节中心距。用关键点直接算会得到
肩胯比 2.0 这种离谱数字（髋关节中心距只有 17cm 左右）。
所以这里逐行扫描人像分割掩码取外轮廓宽度，再用身高做像素→米的定标。

## 已知限制

- **精度**：单目 RGB 的尺度是估计出来的，身高误差约 ±5%，宽度误差更大。
  这是原型，不能当测量工具用。正式管线走深度相机，见主 README 的「系统架构」。
- **遮挡**：手挡住身体、侧身超过 60°、下半身出画时，关键点置信度会掉，
  低于 0.28 的点会被隐藏，人像会出现断裂。
- **性能**：lite 模型 + 分割在桌面 CPU 上约 20-30 fps；开启掩码扫描会再降几帧，
  已做每 3 帧算一次的节流。
- **光照**：画面过暗时检测会直接失败。页面自带自动亮度增益（最高 2.2×），
  但增益只会放大已有的信号——真的没有光，画面全黑时任何提亮都救不回来。
  先把环境照亮，或在系统相机设置里关掉自动曝光手动调高。
- **试衣是简单贴图**：衣服按肩/胯关键点做双线性变形贴在真实人物画面上，
  不模拟布料褶皱、垂坠和遮挡关系，也没有光照匹配。适合看版型和配色，
  不是渲染级效果。深度细节（布料物理、光影、遮挡）是后续的事。
- **镜像**：摄像头画面是 `scaleX(-1)` 的自拍视角，2D 叠加层、3D 人像、
  AD 试衣窗口都跟着镜像，方向才一致。
